# 跨论文研究记忆0.17.0

### 使用方式

覆盖安装0.17.0并完全退出、重新打开Zotero。打开PDF后，插件在后台分批检查同一文献库中已有的对话文件，建立本地索引。设置中的“跨论文研究记忆”显示已索引、待处理、部分记录和需要检查的数量，也可重建索引或关闭自动关联。

提问时，助手结合当前问题、论文标题和近期讨论检索相关记录。讨论A论文时，命中的B论文片段随本轮问题交给当前选择的ChatGPT或DeepSeek。正文中的阅读标记可返回原会话，回答附近的“参考过的阅读记录”可展开查看论文、资料类型、更新时间和实际使用的摘录。历史回答保存当时使用的来源，重开后仍可查看依据。点击早期消息时按需显示附近的消息窗口。

旧记录可能只有会话更新时间，界面会明确标注“会话更新”。摘要使用其正式更新时间，时间字段缺失的旧记录显示时间未知。来源变更或删除后，点击旧引用会展开说明，新的提问会重新检索可用内容。检测到摘要笔记的人工改写时，相关旧摘要退出本轮检索，已完成问答继续作为资料。

### 本地资料与索引

原对话及正式摘要保存在PDF同目录的 `margin-comments-assistant-文献库ID-附件key.json`。派生索引位于Zotero数据目录下的 `margin-comments-assistant/research-memory/`，各文献库分开保存。历史回填使用纯读解析路径，兼容旧版集中目录，当前提问优先于后台批量索引。

首版资料范围按用户选择采用插件保存的已完成问答与正式阅读摘要。检索采用中英文词项和BM25排序，索引建立通过本地代码完成。命中的历史文字作为本轮模型输入，会计入当前服务的输入用量。跨语言同义表达与词汇差异较大的关联仍需要用实际论文检验，当前版本的质量证据来自明确标注相关与无关主题的夹具。

### 资源边界

每轮最多关联三篇论文，单片段最多1800字符，研究记忆上下文最多6000字符，并受现有总文本与请求体积预算限制。当前问题、显式附件及当前PDF先取得预算。

为了控制后台负载，单个历史文件的读取上限为16 MiB，每篇索引最多256000字符或512个片段。每个文献库最多索引2000篇论文，目录文件最多2000000个序列化字符。目录词项优先保留标题、DOI及高频词，详细片段按论文存储，运行时最多缓存八篇论文。部分和跳过状态在设置中显示。这些上限针对派生索引，原始对话文件独立保存。

### 网页端复用与导入导出

设置中的“导出研究笔记”将当前文献库的正式摘要整理成一份Markdown，按论文标题分章，附文献信息和更新时间，并保留LaTeX。用户可将该文件加入ChatGPT项目资料，更新后重新导出、替换项目资料。ChatGPT订阅授权和网页对话访问分别管理，当前插件接入使用逐次传入上下文的方式。[官方授权说明](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)

单个会话导出的JSON保留受校验的研究来源元数据，导入后可核查来源。Markdown、复制回答和保存回答会附上易读的来源摘录。合并连续同角色消息时，来源转换为该段正文中的出处说明。

### 验证结果

完整回归318项通过，耗时168.5秒，全部src JavaScript checkJs通过。新增32项回归覆盖中文及英文检索、明确标题与DOI、无关主题、公式、来源去重、当前会话排除、预算、历史迁移、人工改写、删除或修改的来源、导入导出、设置、真实鼠标点击及早期消息的有界渲染。

大历史回归曾复现约1030毫秒的检索心跳延迟，原因是同一长回答被多个片段重复计算签名和分段。改为在本轮检索内复用校验结果后，检索通过最大心跳间隔小于180毫秒的检查。该证据对应受控的大历史夹具。

异常公式压测还复现了约724毫秒的心跳间隔，大量未闭合定界符触发正则反复扫描。公式与代码分段改用线性扫描，记录已经查明缺少闭合符的类型，并按转义状态识别定界符。修复后未闭合公式、CRLF、多行公式中的行距标记及代码围栏回归通过，异常公式夹具通过180毫秒心跳上限检查。

独立审查发现三项并发及生命周期问题，均增加失败回归后修复。恢复开启时补齐尚未开始的文献库回填，写入期间被前台任务中断的索引工作重新排队，目录文件按文献库串行写入并在队列内取得最新快照。修复及异常公式压测完成后再次运行完整回归和类型检查，最终318项全部通过。

隔离Zotero10.0.7首次启动和冷重启各14项通过，记录位于 `evidence/zotero-0170-memory-v2/report-1.json` 与 `report-2.json`。新增原生检查使用两篇实际夹具PDF，验证A的请求包含B问答、来源与索引冷恢复、来源跳转、历史窗口大小、摘要人工编辑校验、开关和Markdown实际落盘。原有双栏、搜索、剪贴板、数学、自动PDF上下文和阅读摘要检查一起运行。模型推理采用模拟响应，真实账户的回答质量及用户实际语料的关联质量仍需使用中检验。
