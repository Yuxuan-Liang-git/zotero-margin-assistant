# 0.19.2：跨论文检索的通用问法过滤

### 原因

旧版将“这篇论文讲了啥”切成“这篇、篇论、文讲、讲了、了啥”等中文二字片段。其他论文中相同的旧提问也包含这些词，因而可能进入跨论文检索结果。检索材料记录在回答的 `memorySources` 中，便于追溯当轮实际输入；主问答正文保存在 `content` 中。本次报告的无关段落位于检索材料。

扩展查询还会加入当前论文标题和近期提问，因此单靠扩展查询有词命中，无法证明原始问题确实需要查其他论文。

### 修复行为

0.19.2 在查询阶段处理完整的文档指代、通用概述问法、输出语言要求，以及纯符号或公式编号追问。原始问题缺少有效主题时，直接跳过跨论文检索，继续使用当前 PDF 和会话材料；扩展查询中的标题或旧提问不会绕过这项判断。

有明确科学主题、题名或 DOI 的问题继续参与本地检索。科学复合词按原有索引词项匹配，避免通过删除词内子串而损失“条件数”，也保留独立的电流术语 `current`。该修复是保守的关键词相关性过滤；其他主题仍采用已有文本检索，召回质量需要结合具体语料检查。

原索引分词方式保持不变，已有索引可继续使用。升级不迁移或删除用户问答、草稿、摘要和笔记。历史消息中已有的 `memorySources` 保留当时输入证据，新版不会回写过去的来源记录。

### 阅读摘要

每份 PDF 继续维护自己的阅读摘要，以“文章内容、关键公式解释、补充讨论”三个主章节组织，自成体系地解释文章主线、符号、条件和已经澄清的难点。编辑器根据新增理解决定是否需要更新及更新位置，人工编辑保护继续生效。

摘要生成器收集当前 PDF 各会话中已完成的问答正文及当前材料的定位信息，不直接拼接 `memorySources` 的参考材料缓存。若回答正文自身引用了其他资料，摘要编辑仍需判断其关联和归属；本次没有重新生成用户笔记。

### 验证

新增六项行为回归，覆盖中文和英文的通用论文概述、符号和编号追问、扩展查询不能绕过原始问题判断、明确主题和点名文献的检索、科学词保留，以及摘要输入不直接包含外部参考缓存。测试先观察旧代码失败，再验证修复；代码审阅补充的编号问法与科学词反例均已纳入。

完整 `npm test` 405/405 通过，`npm run typecheck` 通过，聚焦检索回归 27/27 通过。最终 XPI 中的实际模块还只读重放了所报告的本地历史记录，原始概述问题的检索材料从 3 条变为 0 条。现有摘要的三个主章节均存在，未找到所指出的无关论文标题及公式标记；这项检查不构成对全部摘要科学结论的审校。

本轮没有启动真实账户推理，也没有修改用户正在使用的 Zotero 配置或论文数据。原生网页恢复仍沿用 0.19.1 已发布的修复，本轮未重跑该版本的网页进程故障注入。向量 RAG 知识库是后续独立扩展，未作为本版已实现功能发布。

### 安装

下载本版 `margin-comments-deepseek-0.19.2.xpi`，通过 Zotero“工具 → 插件 → 从文件安装插件”覆盖安装，随后完全退出并重新打开 Zotero。无需先删除旧版或重建索引。过去 JSON 内的参考材料是历史证据，检查新版行为时以新发送的问题所附带的来源为准。

本地原始验证日志位于 `evidence/memory-0192-validation/`，由 Git 忽略；发布附件提供不含私有对话正文的验证摘要。源码 ZIP 对应版本标签的提交，附件摘要见 `SHA256SUMS.txt`。
