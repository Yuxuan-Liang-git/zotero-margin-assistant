# 云端 Embedding 与本地 RAG 知识库设计

日期：2026-11-10。基于当前已发布的 0.19.2，拟作为 0.20.0 扩展。本文是实现前的书面设计，尚未配置真实云端密钥或开始向量建库。

### 用户目标与已确定的选择

用户希望阅读当前论文时，助手可以利用整个个人文献库中的历史论文回答，即使其他论文没有聊天记录。引用应有可核查出处，并保留当前 PDF 的阅读与交互。用户此前确定整个个人文献库及全部分类的范围，并要求后台执行、不要操作正在使用的桌面。

用户因电脑内存余量有限，已选择云端 Embedding。本地运行回答模型与本地大规模模型推理不进入本次路线。文献分段发送给所配置的 Embedding 服务，向量和来源索引保存在本机；回答继续调用当前配置的 ChatGPT 或 DeepSeek。

阅读摘要继续按“文章内容、关键公式解释、补充讨论”整理为独立笔记。跨论文检索是为本轮回答提供资料的通道，原有会话、草稿、摘要和 Notion 网页保持各自的存储及用途。

### 已勘察的项目与约束

活动开发目录是 D:/AI Tool/zotero-margin-assistant。当前研究记忆由 memory-host.js 汇合既有问答、正式阅读摘要和 library-host.js 的全文来源。papers-v1.sqlite 包含书目、正文、普通笔记和文字标注，使用来源签名、附件身份、页号与已提交 generation 校验时效性。

2026-11-10 只读检查显示，现有索引有 769 条文献、69,240 个片段，文件约 325 MB；这表示现有索引规模，不等于所有 PDF 都已完整识别。本机为 Ryzen 7 7840H、约 32GB 内存，最近一次检查仅约 2.6GB 可用，向量缓存需要有明确内存上限。扫描页继续显示需要 OCR，大文件和部分文字覆盖沿用已有状态。

0.19.2 已拦截一批通用论文概述、符号和纯编号追问引起的跨论文误召回。RAG 保留当前 PDF 和本轮材料的优先级，不能用语义检索重新绕过该约束。既有片段的 memorySources 缓存不作为新知识再次索引。

### 路线比较与选择

本地向量模型可以离线向量化，但需要下载权重并承担首轮计算和模型内存。云端 Embedding 把这部分计算移至服务端，适合当前电脑条件；它需要对应服务的 API Key、网络以及按服务规则控制调用。用户已经选择后者。

云端路线中，推荐采用可配置的兼容 Embeddings 接口，将端点、模型和凭据独立于回答模型管理。默认预设由设计者提出，为硅基流动 BAAI/bge-m3，端点为 https://api.siliconflow.cn/v1/embeddings。其官方模型页列出多语言和 8K 上下文，2026-11-10 官方价格页将普通 BAAI/bge-m3 标为免费；账号权限、限速和价格以后可能变化。不会在遇到限流时自动切换到收费 Pro 模型。

同时提供“自定义兼容接口”配置，允许使用已有服务。首版至少校验 BAAI/bge-m3 和阿里云百炼 text-embedding-v4 风格的契约；自定义模型的上下文与批量限制需要按其服务说明配置。阿里云官方文档当前列出 V4 支持多种维度，北京地域文本输入原价 0.5 元/百万 tokens，批次最多 10 条；具体账号地域及端点由用户填写。

本地检索存储推荐复用 SQLite，并在独立 Worker 中完成向量扫描和排名，避免额外部署数据库服务器。Qdrant、Chroma 等独立服务可提供现成索引，但会增加安装、常驻服务和内存管理，因此首版不引入。混合排名参考 Qdrant 公开的稠密、稀疏与倒数排名融合思路，首版使用项目内可测试的小规模实现。

### 设置与使用流程

“设置 → 页边批注 → 研究记忆”中新增云端向量配置，包含预设或自定义服务、完整 Embeddings 地址、模型 ID、密码类型密钥输入，以及应用、连接测试、清除密钥。向量维度由实际测试响应检测，不要求普通使用者手填。短上下文模型需要的输入上限及批量速度放在高级设置中。

密钥使用独立的 OSKeyStore 加密命名空间；不覆盖 DeepSeek 密钥或 ChatGPT 登录。空输入保留已保存的密钥，测试失败不冒充已保存成功。更换端点时清空未应用的密码输入并提示重新填写，旧端点凭据不会自动发给新主机。服务、模型和索引状态在重启后恢复，密钥明文不写入 PDF 旁的 JSON、日志或导出包。

连接测试只发送固定测试短句，验证响应形状、模型和维度。建库控件提供“试建 20 篇”“开始或继续全库建库”“暂停”，显示已完成、待处理、失效待更新、失败及需要 OCR 的覆盖情况。首版不会因安装插件、填写密钥或打开 PDF 自动启动首次全库云端上传。全库开始后，后续重启恢复队列和暂停状态，允许用户继续；前台对话优先。

配置处明确说明：建库会将文献文字发送至所选 Embedding 服务，原 PDF 和向量索引留在本机。本文对云端向量化的选择已经确定数据流方向，设置内保留用户主动开始建库的操作，避免在用户尚未设置好服务时触发请求。

20 篇试建优先选择当前文献及已有阅读记录的文献，再按稳定的条目顺序补足。试建形成可复用的索引，扩展到全库时不重复请求已完成的内容。它用于确认可用性和实际开销，不宣称这 20 篇能代表整个文献库的检索质量。

聊天栏沿用折叠的来源区，显示材料类型、论文标题、可确认页码以及来源跳转。模型、凭据、批量参数和详细进度集中在设置中。向量库尚未就绪或临时网络失败时，保留已有文字检索，并明确本轮使用范围，正常对话继续。

### 资料范围与云端输入

复用个人文献库已提交的元数据、摘要、PDF 文字、普通 Zotero 笔记及文字标注；同时纳入插件已完成的问答解释和正式阅读摘要。每种资料保留原来的身份标记。用户草稿、未完成回答、待发布或人工冲突中的候选摘要、历史 memorySources 缓存和嵌入附件字节不纳入。Notion 网页内容沿用现有边界，不抓取或向 Embedding 发送。

每个 Embedding 输入由当前论文标题、明确的资料类型和来源文本构成。API 接收文字，不直接上传整个 PDF 文件。源片段与其页码、附件 key、源类型、签名保持关联。相同模型空间内，以完整输入内容的摘要去重；相同输入关联多个来源时可以共用向量，但每个引用保持各自出处。

对超过所选服务输入预算的片段，为向量化创建 Unicode 安全的子段，并记录父片段与子段序号。候选结果回到原片段组装引用，文献来源文字不因向量化子段而被截断或改写。默认 BGE-M3 按每条输入不超过 8000 个 UTF-8 字节控制，包含标题和类型前缀；保留服务拒绝超限后的明确处理状态。短上下文自定义模型可在高级设置调低预算。批量默认 8 条，兼容已核对的两个服务上限，并设置请求总字节预算。

### 云端客户端与凭据契约

客户端使用 HTTPS POST、JSON input 字符串数组及 encoding_format=float，Bearer 凭据来自当前已应用的同一端点配置。默认不发送不受支持的 dimensions、工具或推理参数；只有明确配置了支持可选维度的预设时才加入相应字段。

响应必须完整对应本批输入，index 是唯一且覆盖全批的整数；向量全部有限、维度一致、非零，并与当前空间已检测维度相符。响应中若提供实际模型名，需要与配置建立可核验关系；无法确认模型变化时提示重新测试。尺寸、批次数量和响应体均设上限，失败不会提交半批向量。

缓存空间包含文献库、规范化端点、模型、请求维度策略及格式版本；实际响应维度写入空间元数据。更换模型、端点或维度策略后使用新空间，旧空间不会混入检索结果。即使端点和模型名未变，服务商也可能更新模型权重；提供显式重建入口，不能保证仅凭相同 ID 检测到这种变化。

401、403、明确的额度不足或配置错误会暂停后台建库并显示原因。429 和可恢复的网络、服务错误采用有上限的指数退避，并遵循合理范围内的 Retry-After；不进行无限重试或自动换收费模型。查询和后台批次使用独立的取消控制，停止、关闭、换配置和插件卸载会使迟到结果失效。

### 旧摘要与端点凭据的边界

云端 RAG 将“正式阅读摘要”限定为：存在有效 noteKey、对应 Zotero 笔记仍存在、文献库和父条目归属一致，且原生笔记 HTML 与保存的 noteHTML 一致。只使用已发布的 text，始终排除 pendingText；发生人工编辑或删除冲突时不继续使用旧的正式摘要关联。尚待发布的新候选不会使上一份仍可验证的正式版本失效。

对于只有 text 而缺少 noteKey 的旧记录，本设计选择保留本地数据并标为“摘要待核验”，不把它上传或作为云端 RAG 的正式摘要候选，不自动创建或重写用户笔记。原纯词项模式保持 0.19.2 的读取兼容；云端 RAG 模式的稠密、稀疏及临时回退候选统一使用上述准入规则。人工改写后已作为普通 Zotero 笔记提取的内容，可以按笔记来源参与，并保留“Zotero笔记”身份。用户可通过已有的阅读摘要整理和发布入口恢复正式关联。

Embedding 凭据采用按端点保留的 profile：规范化完整 HTTPS 地址包含主机、端口、路径及非凭据查询参数，作为端点身份的输入；模型和高级参数保存在该端点的 profile 中，加密密钥与对应端点关联。切到已有端点时恢复该 profile 的已保存状态，密码框只显示占位提示；切到未配置端点时不继承上一个端点的密钥，留空表示该端点尚无密钥。清除操作只清当前 profile，切回其他端点不需要重新填写已保存凭据。端点身份的内容摘要与 API Key 无关，日志中不输出 Key 或认证头。

应用端点、模型或凭据变更会使正在进行的测试、建库请求和查询版本失效；模型空间仍由端点、模型和维度策略等确定。请求禁止自动跟随重定向，需用户填写实际 API 地址。该选择由设计者在可实现性审阅后确定，保留多端点使用体验并防止旧 Key 被误发。

### 本地存储、增量与恢复

在 Zotero 数据目录的 margin-comments-assistant/research-memory/ 下新增版本化向量缓存数据库，与 papers-v1.sqlite 及 PDF 旁的会话文件分开。原文、普通笔记、历史 JSON 和已发布阅读摘要继续作为权威数据。向量库可重建，清除它不删除论文、标注、会话或笔记。

向量内容采用归一化 float32 的可验证二进制编码；首版允许使用 SQLite TEXT 中的 Base64 以复用已验证的数据库参数接口。来源关联保存向量键、输入摘要、资料类型、文献与附件身份、原签名、generation 和有效状态。二进制 BLOB 的适配可由实施者在不改变契约的前提下选择，但不依赖安装外部 SQLite 扩展。

后台以稳定游标按批读取已提交片段，将待处理、完成及失败状态持久化。只有请求完成且来源签名、generation、配置版本和运行状态仍有效时，才在事务中发布向量关联。已完成批次在重启后复用，失败或取消不破坏已有效的索引。

源 PDF、笔记、标注、对话和正式摘要变化时，旧关联立即退出有效集合，新内容进入增量队列。删除条目或更换附件后不继续引用旧向量。来源变化但输入内容完全相同的，可复用内容向量并更新关联，减少重复云端调用。配置变化、显式重建和原文更新使用不同操作，避免“暂停”被误实现为清空索引。

### 资源与后台调度

云端只负责生成向量。本地 SQLite I/O 分批异步进行，归一化、缓存构建、相似度计算和融合排名进入专用 Worker。这里的 Worker 是独立计算线程，内存仍计入 Zotero 进程；长期缓存预算之外，在途批次、数据库页缓存和临时数组的总增量峰值需在测试中单独测量。不得在 Zotero 主线程遍历全库向量，不能把全部片段正文一次加载为大型 JS 对象数组。

以现有规模和 BGE-M3 常见的 1024 维估算，float32 向量本体约 270.5 MiB；Base64 存储和元数据会增加磁盘占用。Worker 可从持久 float32 向量逐批构建对称 int8 检索缓存，保存范数以计算余弦，约 67.6 MiB 的向量数据加必要 ID 映射；量化不改写持久向量。实际维度以 API 响应为准，不能硬编码 1024。

内存缓存默认预算 128 MiB，按向量和映射实际分配统计。超过预算时采用分批扫描，在 Worker 中累计 top-K；不能悄悄只检索前若干论文。无任务空闲后释放 Worker 缓存，下一次按需恢复。片段正文只对选中候选读取。用户可见的覆盖数量按有效向量关联计算。

后台同时只发一个建库批次，默认不超过每分钟 20 次请求，并自适应限流。前台提问到来时暂停开启新的后台批次，已发出请求可在有界超时内完成；查询向量使用独立的前台通道，避免排在全库建库队列后面。用户点击暂停仅暂停建库，已有索引仍可检索；关闭云端 RAG 则停止其建库和查询。

默认把语义检索附加等待限制在 8 秒，包含生成查询向量和扫描候选的预算。超时后放弃本轮语义补充并使用已可用的文字结果，不能继续后台累积过期查询。用户取消回答时，本轮查询和迟到消息一并失效。具体批次读取尺寸、空闲释放时间和任务优先级细节由实施者通过资源测试确定。

### 查询、相关性与混合排名

当前 PDF、本轮选区和显式附件优先使用上下文预算。纯粹询问“这篇论文讲了什么”或局部符号、公式编号时，沿用当前文献优先的去噪与门控。用户明确请求关联其他文献时，允许用当前论文标题和当前讨论主题补全查询；不会仅因其他论文有相同的问法就视为相关。

有具体主题的查询同时使用原有词项检索和新向量检索。向量查询由原始问题、当前论文标题及有界的近期主题组成，避免把整段历史或无关的 memorySources 再次拼入。查询向量短期缓存，键包含完整查询、文献指纹及模型空间，换论文或模型不复用错误结果。

候选过滤延续已有边界：当前 PDF 正文、当前父条目的重复元数据、当前会话问答及本轮已提供的材料不重复加入。当前 PDF 已验证的正式摘要或其他会话中确有相关的完成问答可作为本地阅读记忆补充，仍按父文献归组和预算管理。稠密与词项通道各自输出有分数和来源身份的候选，按倒数排名融合处理，并保留稠密通道独立命中的跨语言资料。不得把融合结果重新交给只认可字面词命中的 M.mergeSources 而丢弃语义命中。一个长书或单篇论文不能占满候选，按父文献限制候选并按来源去重。

语义通道设模型空间内的最小相似度与明显不相关的拒绝规则。阈值需要通过正例、跨语言例和负例校准，首版初始值与取舍由实施者记录，不能宣称一个固定余弦阈值适用于所有服务。没有可靠命中时返回空，不为凑满三篇文献而添加材料。

最终沿用最多三篇关联文献、最多 6000 字符、单片段最多 1800 字符的预算。选中后再次核对来源签名、当前 generation、附件身份和可用性，再分配阅读编号进入本轮消息。来源依旧区分论文正文、文献摘要、Zotero 笔记、文字标注、正式阅读摘要和历史助手解释。点击引用前继续核验并跳转原条目、页码或会话。

### 故障与兼容边界

没有密钥、测试未通过或没有向量库时，现有问答、阅读摘要、Notion 和词项检索保持可用。网络失败会显示本轮采用的实际输入范围，原有 PDF 不因 RAG 不可用而缺失。后台任务失败只影响派生向量缓存。

扫描 PDF 和图片公式仍受可提取文字的覆盖限制，向量化不能替代 OCR 或视觉读取。首版继续显示待 OCR 和部分文字状态，不把只有标题的条目报告为“全文已入库”。文本向量的跨语言召回、专业公式表示与学科术语关联需实际语料评估，不承诺覆盖全部潜在联系。

### 验收与证据

先写能复现错误的行为测试，再实现。接口测试覆盖加密保存和冷恢复、端点切换、乱序 index、维度变化、NaN 或零向量、超限、认证失败、429、断网、超时、取消和配置变更后的迟到响应。索引测试覆盖半批不提交、断点继续、重复输入复用、源更新删除及暂停时保留有效索引。

检索测试设置当前 A 论文和从未有对话记录的 B 论文。B 的正确原文通过语义通道命中，在发送请求中有明确身份与页码；另设字面不重合的中英主题和无关负例，确认语义命中不会被词项重排清除，并且原先通用问法的回归仍通过。旧参考缓存不得进入嵌入语料或摘要输入。
