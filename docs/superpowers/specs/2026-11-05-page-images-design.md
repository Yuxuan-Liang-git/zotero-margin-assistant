# 图片阅读、PDF 页面放置与导出

### 需求与现状

用户指出批注里的图片被缩到卡片宽度，内容难以阅读，并要求能够把图片直接放到 PDF 页面上，拖动并固定位置。用户已选择导出或使用其他 PDF 阅读器打开时也能看到图片。此前已批准的图片保存方式为 PDF 专用 Zotero 图片笔记，以及 PDF 同目录的图片副本。

当前0.18.2在批注中只提供缩略图和“打开图片笔记”，缺少原图阅读入口。图片资产保存在 `margin-comments-images/`，关联记录保存在 PDF 旁的 JSON。页内显示已有 PDF.js 页面适配、坐标变换和生命周期管理。原生 Zotero 10.0.7提供 `PDFWorker.export(itemID, path, isPriority, password)`，可先导出带现有 Zotero 标注的 PDF。

### 采用的方式

采用用户已选择的页面放置与带图 PDF 导出方式。阅读时以独立图片对象呈现在页面上，位置按 PDF 坐标保存；导出时把图片合成到一份新的 PDF 中，供其他阅读器查看。将导出目标设为新文件是本设计的实现选择，便于继续维护可调整的图片对象。原有图片笔记与副本继续作为资产保存方式，批注和页面放置共享图片资产。

### 批注图片的阅读

点击缩略图或“查看原图”打开阅读器内的大图查看器。提供适应窗口、100%原尺寸、放大、缩小和拖动平移，支持滚轮缩放和水平、垂直浏览。初次打开适应窗口；长条图片可切到100%阅读。查看器使用原图像素，控件与图片区域各自布局，Esc和关闭按钮退出，并恢复原焦点。旧图片记录直接获得这一入口。

图片操作收在选中时的紧凑控件中，提供“放到 PDF 页面”和“打开图片笔记”。从批注把已有图片放到页面时复用资产，随后在页面调整位置与尺寸。

### PDF 页面的操作

在 PDF 页面的右键菜单提供“在此插入图片”和“在此粘贴图片”。也支持将本地图片拖入页面；PDF 页面获得焦点时可按 Ctrl+V 粘贴截图，初始位置使用最近的页面点击位置或当前页中央。文本输入框、页边批注、文档助手和 Notion 的粘贴继续由各自入口接收。普通文字与链接交给原阅读器处理。

图片按原始比例放入页面，初始尺寸适应当前页。选中后出现拖动、等比缩放手柄，以及锁定、解锁、移除页面图片和查看原图的操作。拖动和缩放限制在所属页内；锁定后保留位置和尺寸，解锁后继续调整。未选中时收起边框与控件。删除操作仅移除这次页面放置，已有图片笔记和共享资产仍可访问。

位置使用 PDF 页面坐标与明确的方向信息保存，涵盖页面旋转、缩放、滚动及非零裁剪框。重开、重启后按同一坐标恢复。每张图片具有独立放置记录，支持一页多图以及同一资产的多次放置。导出顺序与阅读器中的叠放顺序一致。

### 数据与保存

扩展现有图片资产导入，使目标既可为现有批注，也可为指定 PDF 页面。复用文件签名与10 MiB上限检查、原生图片笔记、同目录副本、串行保存和失败补偿。页面导入的笔记保留 PDF 与来源页链接。

在同一 PDF 的本地 JSON 中增加独立页面放置集合，记录放置ID、资产ID、页码、位置、方向、锁定状态和原 PDF 身份。旧图片数据可继续读取，批注图片的关联按原记录恢复。具体字段名和矩形或仿射变换的内部表示由实现者选择，但查看与导出必须共用同一坐标定义与校验。

新格式采用明确的存储版本，旧版本1和2资料在首次迁移写入前生成备份。更新相关导入、检索和存储入口，使已有聊天与摘要可继续读取。旧插件遇到新格式时应按已有保护机制拒绝覆盖，避免旧代码清理未知字段时丢失页面放置。具体版本号和迁移步骤由实现者在计划中固定。

拖动过程只更新画面，松开后提交一次位置。失败时恢复上次成功保存的位置，并给出明确提示。保存与导入、聊天和其他页面操作共享同一 PDF 的一致状态，覆盖并发操作的回归。PDF 文件替换或页码失效时保留图片资产，显示需要重新放置的状态。只读资料拒绝新增、拖动、缩放与移除，仍可查看已保存的图片。

### 导出

提供“导出带图片的 PDF”菜单，用户选择新 PDF 路径。先通过 Zotero 原生导出生成包含现有标注的中间 PDF，再在后台将页面图片按保存坐标合成，完成后原子发布到目标文件。文件选择器处理既有目标的替换确认，插件校验目标与当前原 PDF 路径不同。

PNG、普通JPEG直接按图像数据嵌入。带 EXIF 方向的JPEG按照实际显示方向归一化，GIF和WebP转为静态PNG后嵌入，GIF使用首帧。图像处理保留源像素；定位与旋转覆盖常见四种页面方向和裁剪框。导出的文件包含图片内容，可通过其他 PDF 阅读器查看。

复用已安装的 pdf-lib，随插件打包所需浏览器资源与许可证。PDF 合成放到独立 Worker 中，显示处理状态并支持取消。中间文件与输出临时文件归本次导出所有，失败或取消后清理。加密、文件缺失、无效图片或写入失败时显示具体错误，避免发布不完整文件。导出期间若发生图片或位置变化，使用开始时已确认的完整快照，并明确该次导出的版本。

### 资源与生命周期

每个阅读器只维护一套页面图片监听与查看器。按页面创建、布局和已提交图片变化更新，复用现有页面适配器的布局事件。拖动使用动画帧合并更新，图片数据按需加载并限制缓存；关闭阅读器和停用插件时清理监听、查看器、Worker及临时资源。导出和图片读取避免在 Zotero 主线程进行大段同步 PDF 解析。

### 验收与交付

使用含密集文字和长公式的真实尺寸夹具验证原图阅读，覆盖原尺寸、缩放、平移、关闭和焦点恢复。通过正常右键、粘贴与拖放入口验证新增，检查不同页面、旋转、裁剪、拖动、缩放、锁定、重开和冷重启恢复，以及普通文本粘贴和 PDF 搜索。

把导出 PDF 重新交给独立 PDF.js 渲染，核对图片位置、尺寸、方向、页面数和原有文字与标注，并比较原 PDF 文件哈希。覆盖并发保存、只读、失败补偿、导出取消和源文件变化。完成适用回归、全源码类型检查与原生 Zotero 验证，交付新版 XPI、源码归档和验证说明。版本拟定为0.19.0。
