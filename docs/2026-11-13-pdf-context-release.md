# 0.20.1：普通论文的完整文字上下文

本版修复 ChatGPT 阅读当前 PDF 时被固定 24000 字符预算截成节选的问题。旧版可以成功提取全部页面，却在组装提问材料时只发送部分正文；一份 12 页、约 9.03 MiB 的本地 PDF 在旧策略下只选入约 23900 字符，模型因此无法依据完整方法、理论和实验部分回答。

## 阅读覆盖

符合附件数量、文件大小、页数和请求体预算的 PDF 继续使用完整文件输入。超过这些条件时，ChatGPT 的文字回退最多使用 96000 字符的当前 PDF 文字，并从 120000 字符的请求文字总预算中扣除已有对话、自定义提示词和说明。跨论文材料只在剩余空间中加入。DeepSeek 保持既有预算；整体请求体的 12 MiB 限制仍适用。这些数值是插件自身的保护预算，不表示服务商模型的实际上下文上限。

界面将“原 PDF 未附”与页面图片缺失分开说明。若全部页面的可提取文字进入本轮请求，会显示“文档全文文字”和页数；未发送原文件不会把这部分文字标成缺失。提问说明也明确本轮全文文字已经提供，避免沿用旧对话中的缺页判断。图像公式、图表和提取错乱的符号仍需对应页面图片核对；扫描件、提取失败页或超长文档继续显示实际覆盖，不宣称全部图像已读。

## 验证

四个新增用例均先在旧实现上失败，再在修复后通过。完整回归 517/517、类型检查通过，覆盖文字截断、请求上限、原 PDF 附件路径和覆盖提示。截图中同一份 PDF 的本地重放使用真实 PDF.js 提取、页面渲染、Host 材料准备及 ChatGPT 请求序列化，12 页共 64788 字符的带页码文字进入请求；最终请求约 1.21 MB，包含一页图像。

最终 XPI 在全新、无窗口的隔离 Zotero 10.0.8 中通过首启及冷重启，每次均验证安装启用、12 页文字进入实际提问消息、关闭面板后重新读取并保留历史。两个隔离进程均已退出。回答生成及无关的跨文献查询使用离线替身，没有调用真实 AI 服务，也没有上传用户论文。该验证证明材料准备和来源覆盖，不证明模型的实际阅读或回答质量。

## 使用

安装本版后完全退出并重新打开 Zotero，再发送一次原问题。对于本次复现的 PDF，预期显示“文档全文文字 · 12 页 · 1 页图像 · 原 PDF 未附”。这表示当前文字层已完整提供，图片范围仍以界面列出的实际页面为准。
