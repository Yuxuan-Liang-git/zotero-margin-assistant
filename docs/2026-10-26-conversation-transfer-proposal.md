# 对话导入与导出提案

状态：用户于 2026-10-26 选择“两种都支持：导出文件和粘贴文本”，按此实施；验证记录见 acceptance.md 与 progress.md。

## 目标

把针对论文已有的网页 ChatGPT 问答导入当前 PDF 的对话列表，在插件内继续提问。支持把插件内的一段对话导出备份、阅读、再次导入。保留当前按 PDF 隔离存储的规则，导入不覆盖旧对话，也不改写 PDF、Zotero 数据库或网页账户。

## 方式与取舍

1. 文件导入：支持插件导出的 JSON，以及 ChatGPT 官方数据导出中可识别的 conversations.json；多段对话先选择，再预览。结构化数据能准确保留角色与顺序，但需要先在网页申请并下载导出包。首版选择解压后的 JSON，避免把整个账户压缩包及附件引入当前 PDF。
2. 粘贴文本：提供可编辑文本框，识别明确的角色标题，例如独占一行的“用户：”“助手：”“You:”及“ChatGPT:”，代码围栏内的这些文字不作为角色边界。无角色或角色识别不清楚时不猜测，显示格式示例，要求整理后预览。操作更快，但无法恢复复制过程中丢失的公式和角色。

用户选择两种均支持。导出提供 JSON 与 Markdown 两种用途，不增加外部服务或依赖。

## 使用流程

在“对话记录”页提供“导入对话”；各对话提供“导出 JSON”“导出 Markdown”。主聊天界面不增加常驻设置。

文件选择后先展示候选标题，只将用户选择的一段解析到预览；粘贴入口同样先预览。预览包含目标 PDF、标题、问答数量、角色、正文以及未带入附件等提示。取消不写文件。导入确认后新建独立 ID、切换到该对话，调用现有原子保存流程，保存在 PDF 同目录既有历史文件内；导入失败保留全部原记录并恢复界面状态。生成回答期间不允许导入或切换对话。

JSON 导出包含格式版本、标题、时间、用户/助手正文和必要的回答未完成标记；不包含登录凭据、API 密钥、账户设置、任意本地路径、PDF 内容或附件字节。采用可移植的文字记录格式，不冒充包含全部材料的完整备份。Markdown 保留原始 LaTeX 和问答角色，供阅读归档；首版往返恢复以 JSON 为准。

## 网页对话解释

ChatGPT 官方帮助确认可从设置的数据控制申请导出，下载 ZIP 内含聊天历史；未承诺稳定的 JSON 开发者接口。因此对可识别的 mapping/message 结构按当前选中分支回溯，只导入该路径上的可见 user/assistant 内容；不把不同分支串成一次对话。不导入 system/developer/tool、隐藏推理、登录信息或工具日志。缺少分支定位且有多条可见路径时要求选择分支；循环、损坏结构和未知格式明确报错。

参考：https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data

网页上传的 PDF、图片、音频及其他材料不因文字导入而自动恢复。能识别到的缺失材料在预览中说明；不按外部文件 ID/链接自动下载，不把文字占位符当作附件。导入后每次提问继续走当前 PDF 的自动读取及既有对话压缩逻辑；长记录不会一次无界送入模型。导入文字是历史消息，不提升为系统指令，不声称恢复网页内隐藏上下文或获得网页对话控制权。

## 实现边界

新增独立转换模块，复用现有 core 校验、Host 文件选择与读写能力、Panel 对话列表及保存逻辑。限制文件大小、消息数和单条正文长度；先校验后写入，不执行任意 HTML，不读取导入文件携带的路径。多会话导出文件逐条选择导入，避免把账户所有历史自动写进某篇论文。

不修改现有来源索引、材料指纹和 PDF 批注。跨 PDF 的引用材料不直接沿用为有效来源，导入只保留文字，避免触发来源失效或读取错误文档。

## 验证计划

- 结构化 JSON 往返，角色/顺序/LaTeX/Unicode/未完成标记保留；重复导入使用新 ID，现有对话不变。
- 网页 mapping 的分支、无效结构、工具及隐藏消息排除、缺失附件提示。
- 粘贴文本角色、代码围栏、缺失角色、多轮与末尾未回答问题。
- 空文件、未知版本、超限、读取失败、写入失败、取消时零覆盖；长文件上限与响应性。
- UI 的选择、预览、取消、导入后继续发送；校验请求含导入的问答和当前 PDF 背景。
- 完整回归、类型检查、XPI 资源验证；在独立 Zotero 配置中验证首启和冷重启后保留导入记录，保持用户真实配置不变。
