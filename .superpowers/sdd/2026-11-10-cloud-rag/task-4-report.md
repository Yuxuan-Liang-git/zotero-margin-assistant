## Interfaces and adapter contracts

`ZMARAG.Manager({profiles,client,store,runtime,corpus,validate,hash,controller,foreground,notify,libraryID,now?,sleep?})` retains injected components as ordinary properties. Public lifecycle: `start`, `state`, `settingsAPI`, `retrieve`, `suspend`, `refresh`, `prioritize`, `stop`; `work` is its actual background work promise. `settingsAPI` provides `state(endpoint?)`, `watch`, `apply`, `test`, `clearKey`, `setEnabled`, `pilot`, `build`, `pause`, `clearIndex`. Build/pilot schedule rather than await indexing. Install, apply, test, enable and prioritize do not authorize first corpus upload.

`ZMARAGHost.create(host,{history,readRecord,papers,enabled,notify})` returns an optional manager. It uses Zotero Prefs/OSKeyStore, runtime crypto SHA-256 and Worker, and an independent `research-memory/vectors-v1.sqlite`. Unavailable capabilities return null; load/config failures become safe status and leave normal PDF chat available. `host.memory.embedding` and `host.settingsAPI().embedding` expose it. `host.createRAGWorker` loads `chrome://margincomments/content/rag-vector-worker.js`. Memory stop closes both old managers and cloud resources.

`ZMARAGHost.Corpus({libraryID,papers,history,readRecord})`: `sources({cursor,limitPapers,signal})` yields `{source,cursor}`; source is the original full cleanSources-compatible fragment, not a shortened embedding input. Cursor is JSON phase/library chunk ID or history attachment/ordinal, plus bounded pilot parent identities. `validate(source,signal)` checks committed index plus actual Zotero authority for v2; historical sources use stable sidecar `readRecord`, sourceCurrent and (for summaries) a real matching noteKey/native note. No staging rows, draft/pending summaries, incomplete answers, memorySources or Notion content are enumerated. Ordinary edited native notes remain notes. Cloud eligibility is stricter than legacy lexical summary compatibility.

Minimal earlier-module extensions, both regression tested: `LibraryIndex.sourcesPage({afterId=0,limit=128}) -> {phase:'library',cursor,sources:[{source,cursor,phase}]}` joins active committed generation and paper rows; `Store.pending(namespace,limit=8,source?)` optionally filters source anchor in SQL before LIMIT, preserving 2-argument behavior and avoiding starvation behind stale pending inputs. No SQLite schema changes. Profiles accepts optional per-endpoint `threshold` in [0,1]; old stored profile shapes remain valid, default is 0.45. Threshold is a starting policy, not calibrated cloud evidence.

## Behavior and persistence

Space namespace is SHA-256 of personal library identity and the tested endpoint/model/actual-dimension namespace. Inputs are SHA-256 keyed Unicode code-point segments with title/type prefix; byte cap is min(configured,8000). At most min(configured batch,8) inputs per request; default background rate is20 requests/minute. Batches currently follow source authority boundaries and can contain fewer than8 inputs. Retry transient failures at most3 times after the initial attempt, with Retry-After bounded to60 seconds; authentication/configuration/non-retryable errors pause. `batchFailures` is a coordinator lifetime count of failed batches; Store.failed remains0 for success-only storage.

Scan control uses existing `{mode,paused,cursor,scanID,completed}` allowlist. Restarted incomplete tasks remain paused. Successful cached inputs are reused. Only a completed full scan prunes missing sources; pilot never prunes valid full-cache sources. Full authorized mode debounces incremental refresh500ms. Pilot source refresh **pauses the pilot**, preserving valid vectors and requiring another explicit pilot/full click; ordinary open/save/new priority cannot rotate a20-paper cohort and cumulatively upload21+ papers. Foreground suspension affects new background batches only. Source and profile checks reject late callbacks; pause/stop release unresolved external corpus waits and cancel default backoff timers.

Foreground uses the raw question gate and a separate8,000ms deadline, even while blanket Host.memory.pause is active. Current PDF body, its parent metadata and active conversation are excluded before Worker truncation. Dense candidates below threshold are discarded; validated sparse candidates remain available. Fusion uses vector-core hybridSelect and does not run legacy lexical merge afterwards. Candidates are validated before fusion and selected sources validated again; final limits are3 papers/6000 chars/1800 chars per fragment. Index commits do not reset an active Worker query merely because new vectors arrived. Worker idle cache is released after60 seconds; stop ends timers, requests, Worker and DB.

## Task 4 fixround1 — three Important review findings

This section supersedes the source-boundary batching concern and old pilot-selection description above. The implementation was corrected in one scoped wave; native/cloud acceptance boundaries remain unchanged.

1. Cross-source batches: the coordinator now accumulates up to min(configured batchSize,8) unique pending inputs across source owners. A shared input hash is transmitted once with all owners retained. Every owner is revalidated before transmission and after response; any invalid owner prevents publication of the complete mixed batch. Store.commit retains its synchronous generation/config/cancellation predicate and transaction rollback behavior. Source-scoped Store.pending is preserved, so unrelated stale inputs are never sent. A durable source cursor advances only across contiguous fully enumerated sources whose pending keys all committed. Buffered owner/source objects are bounded to128 jobs; an all-duplicate or small tail can flush below8 inputs. Ordinary10-source fixture produces batches[8,2], and9-source/8-unique fixture produces[8]. The former~57.7h single-input batching concern is resolved for ordinary fragments; no actual cloud throughput measurement is claimed.

2. Pilot priority and fixed cohort: selection is current paper first, then papers with eligible completed reading history/verified summaries, then stable paper-key order to20 parents. MemoryHost supplies the actual current owner; an attachment-only priority can be resolved from the committed index. The selected ordered `cohort` is persisted in scan cursor JSON before the first document network request. Pilot source enumeration follows that cohort, with `paperAt` and `afterId` for committed library pages. Resume uses the persisted cohort despite a changed current reader; older partial `papers` cursors retain their already-used subset. Automatic source refresh still pauses a pilot and requires a fresh explicit pilot/full action, so priority changes cannot silently rotate or expand upload scope. The23-paper fixture selects current23rd, reading-history22nd, then the first18 stable papers; a real Manager/Client/Store run proves the same cohort is durable while the first mixed request is in flight.

3. Connection-test lifecycle: connection tests use a tracked controller, manager generation, and cancellation race. Stop/config changes abort the actual fetch signal and release the test promise even when external credentials/profile work is queued. A late response cannot begin tested-profile persistence or configure the vector store. The profile validity guard runs inside its serialized mutation as well as before/after the call, covering shutdown while markTested waits behind a credential operation. Native Prefs.set is synchronous: a save already begun before cancellation is not rolled back, and no hypothetical asynchronous storage rollback was added. Tests deterministically block real Profiles.credentials decryption, queue the test mutation behind it, stop or change config, then release the queue; tested remainsfalse.

API extensions in this fix wave: `Profiles.markTested(dimensions,actualModel,expectedRevision,valid?)` adds an optional validity predicate while preserving the existing revision argument; `LibraryIndex.sourcesPage({afterId?,limit?,paperKey?})` optionally selects one committed parent; `LibraryIndex.paperForAttachment(attachmentKey)` resolves committed PDF ownership. No schema change. `Corpus.sources` keeps `{source,cursor}` and optionally adds `checkpoint` on the first pilot entry; this checkpoint pins selection without advancing beyond any uncommitted source. Existing settings IDs and state fields are unchanged. The test fixture's external authority validator now checks anchor identity as well as signature/fingerprint, so a different owner with identical text cannot make an obsolete owner appear current.
