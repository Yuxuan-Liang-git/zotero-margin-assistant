# 0.13.7 底部输入框高度修复

用户确认问题是底部消息输入框的高度。原样式只有原生 textarea 右下角的 `resize:vertical` 手柄，并以180像素限制高度，放在底部固定的 composer 中难以向上扩展。

改为输入框上沿的横向拖动手柄，向上拖动增加高度，向下拖动减小。使用 pointer capture 保证指针离开手柄后仍完成拖动，取消/失去捕获时停止。手柄支持键盘上下方向键（Shift加大步幅）、Home/End和屏幕阅读器的 separator/aria-value；不抢走正在编辑的输入框焦点或改动其草稿/选区。

按聊天区实际高度、其他控件占用、输入字号计算范围，预留回答区80像素，窗口缩小时重新约束。保留当前侧栏关闭/再打开的高度，销毁时断开 ResizeObserver 和窗口监听。未新增定时轮询或写入历史文件。

验证：

- 新增两项回归，修复前均失败；修复后真实浏览器鼠标向上拖动超过原180像素上限，缩小、保留草稿和光标、关闭/重开、480像素小窗口、键盘、取消与销毁通过。截图 `evidence/ui-0137/composer-resized.png` 已检查。
- 完整测试215/215通过，147.3秒；全部src checkJs通过。记录：`evidence/ui-0137/tests-final.txt`。
- 原生 Zotero 测试使用隔离配置，AI输出模拟，包含既有20项功能和新增输入框缩放步骤。结果和冷重启证据：`evidence/zotero-0137-composer-v2/report-1.json`、`report-2.json`。原生指针事件是合成事件；真实拖动由浏览器回归覆盖。
- 初轮原生探针错误地要求拥挤的测试窗口也必须展开超过180像素，实际可用上限为133像素，输入框按该上限正确展开，故该断言失败。已按实际 `aria-valuemax` 验证原生窗口的边界行为；较大浏览器窗口另行验证超过180像素。没有更改生产逻辑或缩减测试内容来忽略窗口边界。
