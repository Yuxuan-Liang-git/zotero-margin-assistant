## Corrected behavior and contracts

1. Master research-memory switch: MemoryHost now checks the master setting at retrieval entry, after asynchronous lexical collection and before returning results. A switch generation prevents an old request from returning sources after an off/on transition. Changing the switch invalidates active RAG work; the real Host supplies `enabled:()=>boolean` to Manager, so disabled startup and direct Manager retrieval also respect the master. Master-off blocks background launches and returns no memory sources, including lexical fallback, while preserving Embedding profile enable/key/test preferences. Host.claimRequest/background pause continues to suspend background batches without disabling foreground retrieval.

2. Semantic input: the raw question remains the gate for generic overview/symbol/formula requests. Once eligible, the actual POST input consists of the raw question plus the expanded query's title/recent-theme context, with a duplicated initial question removed. The complete input is Unicode-code-point bounded to min(configured maxInputBytes,8000) UTF-8 bytes. The byte cap includes all context. Tests assert actual POST text, not a mocked vector API.

3. Hybrid ranking: per source anchor, vector-core retains the best dense contribution and best sparse contribution separately and sums them. Repeated entries within a channel count once. A dense-rank2+sparse-rank1 agreement now outranks a dense-only-rank1 candidate under maxPapers1; dense-only cross-language retention, scope exclusions, diversity and final budgets remain unchanged. The exact Worker scoring/scan algorithm is unchanged.

4. Dirty full continuation: unpausing an authorized full scan with refreshPending schedules the existing fresh full-scan path immediately. Completed=true no longer prevents the refreshed scan. Already successful input vectors are reused, the new source is indexed without a second event/build click, and pilot refresh still requires explicit authorization. The pre-authorization pause/continue regression confirms it cannot start a first corpus upload.

5. Query-vector cache: Manager accepts optional `fingerprint(scope,signal)->Promise<string|null>`; retrieve also accepts `options.fingerprint` as an explicit identity override. Actual RAGHost supplies SHA-256 of native attachment/library/parent identity, file path, byte count and modification stamp. Missing/unavailable current-PDF identity disables cache use conservatively. Cache keys are SHA-256 of the complete bounded semantic POST input, current-PDF fingerprint, attachment/library identity, tested model namespace and profile revision. Values contain only `{vector,expiresAt}`, never a service Key, source bytes or query plaintext. At most32 entries are retained, with a60,000ms TTL and bounded LRU replacement. Configuration/master/source invalidations and stop clear it; changed input, title/theme, file identity or model cannot incorrectly reuse a vector. Only fully successful, uncancelled retrievals insert a new entry. Failure/abort removes the attempted entry. Current source validation and local scans still run for cache hits.

No settings IDs, profile schema, vector schema, persistent source formats or model defaults changed. Newly exposed ordinary Manager fields are `enabled` callback, `fingerprint` callback and `queryVectors` Map. Cache state is runtime-only and is not included in sidecars, exports or settings state.
