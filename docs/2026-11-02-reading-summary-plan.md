# 阅读摘要实施计划

### 目标与约束

实现已确认的docs/2026-11-02-reading-summary-design.md。沿用纯JavaScript、现有Zotero接口、Markdown与公式显示器，保留baseline及日常配置。本目录没有Git仓库，直接在当前工作目录修改并以源码归档和验证报告保留变更；不创建Git仓库或操作真实文库。计划和记录采用完整段落，遵循用户的行文要求。

### 摘要核心与存储

新增src/reading-summary.js，公开clean、collect、parseResult及Manager。摘要数据readingSummary进入既有core.cleanState，保持version2兼容。先写tests/reading-summary.test.cjs与core回归，覆盖跨会话完整问答、分批进度、无变化、失败/取消保留、长输入、原样LaTeX和无图片字节，然后运行观察失败，再实现。

Manager统一调度各PDF，自动空闲20秒、每次至多处理两批，后续仍有内容时继续排队。前台提问取消后台请求，过期结果不发布，导入和新问答纳入进度。提示与输出长度受控，模型输出明确给出是否改变和摘要正文。先保存有效候选及进度，再同步Zotero笔记，失败保留候选等待后续重试。

### Host与Zotero笔记

Host提供摘要配置、持久化、发布和打开笔记接口。按PDF标识定位本插件笔记，保存后记录getNote返回的基准正文。人工修改/删除时保留原笔记并留下待合并候选，用户应用候选时另存新摘要版本，原人工版本保留。该选择将设计中的手动保护落实为可逆操作。原生笔记的数学HTML遵循本机note-editor模式，助手使用原有Markdown/MathML显示。

通过适配器单元/浏览器测试覆盖标题、父条目、相同PDF去重、不同PDF隔离、只读、人工改写、保存失败和并发草稿。失败测试通过后接入回答保存成功、首次打开与导入后的调度，以及关闭/停止时的取消清理。

### 阅读入口与设置

助手顶部增加阅读摘要入口和小幅状态提示，独立页面显示本地正文、更新时间、待更新或失败状态，提供更新与打开Zotero笔记。已有摘要在重开时直接读取；首次无摘要时说明生成状态。设置增加自动更新开关和额度说明，不在聊天主界面增加模型配置。界面使用连贯段落和现有公式渲染，保留聊天草稿和滚动位置。

先补界面回归验证本地重开、状态、手动更新、人工改写保护和禁用自动更新，再实现集成。整个功能遵循原有并发导入/保存保护，摘要变化不触发页边引用重绘。
