# 整个个人文献库的论文记忆

日期为2026-11-04，基于0.17.0扩展，拟交付0.18.0。用户已确定范围为整个个人文献库，包含全部分类文件夹。

### 目标

打开A论文提问时，助手可根据个人文献库中B论文的摘要、正文或相关笔记建立联系，即使B尚未有插件对话记录。回答给出可核查的出处，区分论文原文、用户笔记和历史助手解释，并允许回到条目、PDF页面或原会话继续阅读。

现有0.17.0索引从PDF旁的插件历史文件读取问答和正式摘要。扩展后以个人文献库条目为发现入口，将文献信息、PDF及笔记作为独立资料来源。资料的覆盖范围随实际可读取内容记录。

### 范围与资料

统一枚举Zotero个人文献库中的正常文献条目、独立PDF附件及其本地内容，分类文件夹作为组织信息。同一文献属于多个分类时合并处理，多个PDF版本保留各自的附件标识及出处。已有问答和阅读摘要参与同一轮检索。

所有文献首先纳入标题、作者、年份、DOI、摘要和标签。已有本地PDF逐步建立正文索引，普通Zotero笔记、PDF文字标注及其批注也作为带身份的来源。插件生成的历史入口快捷笔记采用入口属性，重复的正式摘要和同一段正文在检索组装时去重。此次资料范围扩展由设计者提出，随本设计确认。

只有文献信息的条目可通过摘要和书目信息参与引用。正文覆盖状态分为已就绪、处理中、部分文字、需要OCR、文件缺失、需要密码或提取失败，设置中显示数量及可处理原因。资料来源在回答中注明“文献摘要”“论文正文”“Zotero笔记”“PDF标注”“阅读摘要”或“历史问答”。

### 已核对的本机能力与实现路线

本机Zotero10.0.7源码提供 `Zotero.Fulltext.getItemCacheFile()`、`getIndexedState()` 和 `findItemsWithContent()`，可复用已建立的全文缓存与内容索引。`Zotero.SDT.getReader()` 复用或生成结构化文本包，其读取器提供目录及 `getPageBlocks()`。结构化提取通过Zotero的文档Worker执行，可以在PDF阅读器关闭时读取附件。以上结论来自安装包源码检查，运行行为在隔离Zotero中验证。

采用本地全文检索路线，优先使用有效的现有缓存和索引。需要建立正文时，调用Zotero后台结构化提取接口，逐篇分批处理。实现阶段核对数据包格式和页码语义，按页及段落保存可定位片段。运行版本缺少结构化接口时，使用已有全文缓存或后台普通文本提取，出处显示可核对的文字节选，定位通过打开PDF及搜索该片段完成。

论文正文采用单独的分段检索通道，覆盖个人文献库中全部已发现的文献。0.17.0针对对话索引的2000篇和每篇256000字符限制继续归属于相应资料类型，正文通道按页、分段存储及查询预算管理覆盖范围，长书籍的后半部分也须可被检索。具体磁盘结构及复用Zotero全文索引的边界由实现者根据实际接口验证确定。

### 后台处理与性能

启动后首先分批同步文献元数据，再处理已有正文缓存，随后在空闲时补充缺少文字索引的本地PDF。单次仅运行一个后台文档提取任务，文字分段、候选排序和索引写入均分批让出事件循环。当前阅读的文献、最近新增文献及明确点名的文献优先取得处理机会，进度随分类无重复地汇总。

前台提问优先使用已完成的索引。Zotero文档Worker已经开始的单个任务可能继续执行到结束，取消后丢弃过期结果，后台队列暂停后续文献的处理。关闭设置或停用插件时，提交前再次核对任务版本和运行状态。后台工作与前台阅读分开记录进度。

提取前检查文件体积，对大文件设置明确的内存预算。首版拟将自动后台提取的单个PDF限制为64 MiB，超过该范围显示“大文件待处理”，书目信息及已有缓存仍可用于检索。这个初始阈值由设计者提出，实际夹具验证后记录在发布说明中。索引容量、页数及缓存上限以明确的部分或跳过状态呈现，检索界面保持可用。

### 扫描件与公式

已有OCR文字层按普通PDF正文处理。纯图片页面记录为需要OCR，文献的标题、摘要和已有笔记仍可作为来源。首版利用本机已有文字层及Zotero文本提取能力，自动批量AI识别扫描页属于后续可独立启用的处理阶段。提取到正文文字时，仍需保留图像公式缺少可读文本的覆盖说明。

当前PDF的选区、截图及已有图像提问继续通过原有阅读路径参与回答。引用其他论文时，有可靠页码的文字片段带页码，只有文献信息的来源带条目入口。模型依据本轮实际提供的文字或图像说明结论与适用条件。

### 检索与上下文

检索先从个人文献库的标题、摘要、标签、笔记及全文中筛选候选论文，再对命中的页与段落排序。候选库涵盖尚未有对话记录的文献。明确提到标题或DOI时优先定位该条目。正文、笔记与历史讨论分别标记身份，同一论文的多种资料可相互补充。

沿用每轮最多三篇论文、最多6000字符的关联上下文预算，单个片段最多1800字符。当前问题、显式材料及当前PDF优先取得预算。后台文本提取与索引在本机执行，选中的其他论文片段随正常提问提交给当前AI服务。检索继续采用本地文本相关性方法，跨语言同义关联纳入质量边界。

### 出处与变化校验

每个来源携带个人文献库ID、父文献key、附件或笔记key、资料类型、内容签名，以及可确认的页号、段落或消息位置。没有PDF的来源打开对应Zotero条目，笔记来源打开原笔记，正文来源打开PDF并定位到页或文字，历史来源沿用会话跳转。旧版来源数据保留其读取方式，新增字段有独立的合法性和长度校验。

正文结果在用于提问或点击前核对附件身份、文件或结构化包的指纹。条目、摘要、笔记和标注的修改触发增量更新，删除或替换后的片段退出当前候选。模型只能引用本轮实际提供的来源，资料中的指令文字按阅读材料处理。

### 设置与本地保存

设置中的“跨论文研究记忆”升级为个人文献库的统一入口，提供总文献数、元数据就绪数、正文就绪数、处理中及需要处理的状态。可暂停、继续或重建正文索引，操作集中在设置中。回答附近沿用折叠的来源区。

派生资料保存在Zotero数据目录的 `margin-comments-assistant/research-memory/` 下，使用可识别的版本及资料类型区分旧会话索引与新正文索引。正文提取可复用Zotero自己维护的结构化及全文缓存。原PDF、书目、普通笔记及对话记录分别作为其资料的权威来源。

“导出研究笔记”继续导出已有正式阅读摘要。没有AI阅读摘要的论文可在导出中显示书目信息与正文覆盖状态，索引片段以文献节选的身份显示。为全库生成新的AI摘要属于单独的推理任务，首版的全库纳入通过本地资料索引完成。

### 验收

建立一篇A论文和一篇从未有过插件历史文件的B论文，通过正常提问入口确认B正文进入请求并可点击回到原页。另设只有摘要的条目、普通笔记、文字标注、多个分类中的同一文献及有多PDF版本的文献，验证身份、去重、出处与内容覆盖状态。

扫描件、部分文字层、缺失文件、需要密码、超过体积预算和提取失败各有独立回归。长文献末尾的唯一关键词必须能命中，超2000篇条目的夹具必须保留全库发现能力。后台处理中进行提问、暂停、取消、重启、修改或删除来源时，索引结果保持一致。

完成原有全部回归、全源码类型检查、异常公式及大历史性能测试，并在隔离Zotero中使用真实夹具PDF验证结构化提取、正文引用、分页跳转、缓存恢复与升级。AI回答使用可检查输入的模拟响应，实际语料的关联质量另行标明。交付新版XPI、源码归档及与最终包哈希一致的验收报告。

### 确认内容

用户已确定整个个人文献库及全部分类的范围。待确认的扩展路线为本地索引文献信息、已有PDF正文、Zotero笔记及标注，优先复用Zotero后台提取与缓存，并对扫描件及大文件展示覆盖状态。64 MiB后台自动提取阈值及正文通道的独立覆盖策略由设计者提出。接口适配、磁盘格式、分批尺寸、检索阈值和测试夹具由实现者在上述契约内确定。
