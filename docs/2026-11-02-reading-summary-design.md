# 阅读摘要笔记设计

### 使用目标与方案

同一份PDF拥有一份跨会话的阅读摘要，打开文献后即可回顾此前已经澄清的难点，继续此前的理解过程。完整对话仍按原方式保留。摘要重点记录用户提出的问题及其中有复用价值的解释，不把整篇论文的通用概述作为主要内容。

建议采用每份PDF一份、基于新增问答逐步维护的摘要。按会话分别保存多份摘要适合独立归档，但回顾同一篇论文时仍需逐份查看；每轮从全部历史重写可以简化处理，却会增加请求长度和重复计算。本方案复用现有按PDF保存的对话及笔记接口，持续维护一份可直接阅读的结果。

### 内容与写作

摘要使用中文连贯散文，以简短标题组织。内容围绕此前难以理解的概念、关键推导及适用条件、符号和公式之间的联系、已澄清的误解以及尚未解决的问题展开。保留有依据的公式编号、PDF页码和必要的来源链接，公式使用现有数学分隔符与渲染方式。明确区分原文依据、对话中的推断和待核对之处，避免把助手未经确认的解释写成论文已经证实的事实。

生成提示遵循用户最新的行文要求，采用完整段落，减少项目符号，不使用加粗、斜体或“不是……而是……”句式。无新增有用知识时允许保持原文，不为每次闲聊追加内容。

### 更新时机与请求

每次完整回答保存成功后，将相关PDF标记为待检查。默认等待20秒空闲，再用当前选中的ChatGPT或DeepSeek服务判断新增问答是否值得纳入笔记。连续追问会合并待处理内容；用户提问优先，后台任务可取消并稍后继续。HTTP错误、空回答和中断回答不会被当作完整结论写入笔记。

模型只接收已有阅读摘要和受长度约束的新增问答，不重复上传整份PDF或附件。首次生成覆盖该PDF已有的各段对话，长历史分批处理；后续依照处理进度增量更新。每个PDF同一时刻只允许一个摘要任务，避免旧任务覆盖新结果。失败时保留旧笔记及待处理进度，显示更新未完成，可手动重试。当前ChatGPT HTTP400若继续发生，也会影响自动摘要生成。

关闭助手不会删除笔记；退出Zotero时取消尚未完成的请求，待处理进度保留，下一次打开后继续。自动摘要会额外使用当前所选服务的请求额度，可在设置中关闭，助手内保留手动更新入口。

### 保存和阅读入口

创建独立的Zotero“阅读摘要”笔记，与当前PDF所属文献关联，以附件标识区分同一文献下的多个PDF。助手提供“阅读摘要”入口，显示最近保存的内容、更新时间和是否还有待合并的问答，并允许打开原生Zotero笔记。重新打开PDF时直接显示本地已有摘要，读取过程无需等待模型。

阅读摘要的正文、处理进度和笔记标识随现有PDF同目录的对话JSON保存，以便恢复和继续更新。此方案不再增加单独的Markdown副本。现有历史格式兼容读取，没有摘要数据的旧记录按首次生成处理；导入对话会被纳入后续摘要。

自动写入只定位本插件创建的对应摘要笔记。发现用户手动改写该笔记时保留其内容，将新生成的结果显示为待合并版本，待用户查看后应用。其他笔记不受影响。文献库只读、PDF目录无法写入或笔记保存失败时，保留已有内容并显示具体状态。

### 实现边界与验收

新增独立的阅读摘要模块，负责可用问答筛选、增量批次、结果校验和任务调度；Host负责对应PDF的持久化及Zotero笔记，Panel负责阅读入口和状态。阅读摘要与供模型续聊使用的压缩摘要分别维护，不改变原有聊天上下文压缩规则。

验证重点为跨PDF隔离、跨会话汇总、无变化时不重写、模型错误或中断后旧笔记保留、生成与新问题之间的优先级、旧任务结果作废、重启恢复、导入记录纳入，以及用户手动改写的保护。使用隔离配置与模拟推理完成自动化测试，打包前运行适当的全套回归与类型检查，不修改日常文库进行测试。

本设计已由用户确认，并在0.14.0实现；验证范围见同日reading-summary-release文档。
