# 0.20.0：独立 Embedding 与全库语义检索

本版为个人文献库增加可选的云端语义检索。阅读当前 PDF 时，插件可以从其他文献的已提交文字中寻找含义相关的片段，并保留标题、来源类型、原文页号或会话入口。默认使用 SiliconFlow 的 `BAAI/bge-m3`，完整端点为 `https://api.siliconflow.cn/v1/embeddings`；也可配置兼容 HTTPS 端点与模型。对话仍由用户选择的 DeepSeek 或 ChatGPT 服务完成。

## 配置与开始

请在 Zotero 的“设置 → 页边批注 → 云端语义检索”中填写自己的 Embedding API Key。这个 Key 与 DeepSeek 对话密钥、ChatGPT 账户授权分别管理。插件使用 Zotero 系统密钥库加密保存，并按完整规范化 HTTPS 端点隔离；新端点的空密码框不会沿用其他端点的密钥。切回已保存端点可恢复自己的配置。

保存配置后点击“测试连接”。测试发送固定短句，成功后再启用语义检索，并明确点击“试建 20 篇”或“建立／继续全库索引”。安装、保存配置、测试连接和打开 PDF 都不会触发首次全库上传。建议先用二十篇试建核对原文覆盖、来源、费用和中文问题的检索结果，再决定扩大范围。服务价格、额度和限速由服务方决定，插件不会自动切换收费模型。

默认每输入最多 8000 UTF-8 字节，每批最多八条，后台每分钟最多二十次请求。批次可能少于八条，大型文献库首次建立可能持续数小时。例如七万条输入即使持续以每批八条、每分钟二十次处理，也约需七小时十八分钟；实际还包括提取、划分、限流和重试。打开的 PDF 获得后台处理优先级，对话进行时新的后台批次让出资源。暂停会保留有效向量，未完成任务在重启后保持暂停，用户明确继续后再处理。

## 资料、来源与本地数据

Embedding 材料来自已提交的文献信息、PDF 可提取文字、普通 Zotero 笔记、文字标注、可核对身份的正式阅读摘要和完整历史问答。草稿、待整理内容、未完成回答和历史检索来源缓存不参与建立向量。缺少原生笔记身份的旧纯文本摘要保留原数据，等待核验。Notion 网页继续用于独立阅读，不会自动进入 AI 材料。

扫描 PDF 需要先完成 OCR；图片公式、图表和未识别文字可能没有向量覆盖。自动正文提取上限仍为 64 MiB，更大的文档优先使用已有缓存。覆盖计数反映已处理资料，试建或暂停时只代表部分覆盖。正式阅读摘要继续组织为文章内容、关键公式解释和补充讨论，不把历史检索缓存直接当作新的理解材料。

云端服务负责将提交的文字转换为向量。本地 SQLite 保存向量与来源关联，Worker 分批扫描并结合词面结果、来源有效性和上下文预算筛选。每轮最多引入三篇文献、每篇最多四段，每段最多 1800 字符，整体约 6000 字符。当前 PDF 材料继续单独准备。通用概述、纯符号与公式编号追问会跳过没有明确主题的跨文献检索，没有可靠候选时可以返回空来源。

派生向量位于 Zotero 数据目录下的 `margin-comments-assistant/research-memory/vectors-v1.sqlite`，与正文索引 `papers-v1.sqlite` 分开。“清除派生向量索引”只清除当前端点、模型和维度空间的派生数据及进度，保留 PDF、原始会话、阅读摘要与正文索引。重新建立可能再次消耗服务额度，索引需要自行备份，不承诺通过 Zotero Sync 同步。

## 回退与验证边界

前台语义检索的附加预算仍为八秒，包含查询向量请求及本地检索。无 Key、断网、服务失败或超过预算时使用有效的本地结果，当前 PDF 和普通对话继续可用。来源在云响应前后发生变化时，过期结果不能作为当前资料发布。向量相似度只能提出相关候选，默认阈值 0.45 尚未针对真实服务校准，科研结论仍需回看原文条件。

原生自动化使用全新隔离配置与自编 A/B/C PDF，保持真实的 Zotero 系统密钥库、SQLite、PDF 结构化提取、Worker、设置控件及原文跳转。仅 Embedding fetch 和对话生成这两个外部边界使用确定结果，没有访问用户文献库、私密凭据、实际桌面或真实云端服务。测试中的中文问题与 B 的英文正文没有共同字面词，B 没有历史会话；其第二页原文通过实际 A 提问请求进入上下文，并可跳回该页。

原生验收还发现了不同 JavaScript 环境之间的有效字节流被误拒绝的问题。本版使用实际字节数组类型验证兼容该边界，继续保留响应大小、向量数值、维度与模型身份的检查。八秒内无法完成的大规模检索仍会取消并回退，检索时间会随设备负载、缓存、文字量和服务响应变化。

真实 Embedding 服务的中英文召回质量、学术相关性、阈值、费用与网络表现尚未验证，需要用户在 Zotero 填入自己的 Key 后核对。合成向量测试证明数据处理和来源链路，不能解释为真实全库云端建立或科学相关性验证。

## 安装包与复现记录

最终 0.20.0 XPI 的 SHA-256 为 `ecea7c3bd4257f01fab6a057eb65f31856cc3613aeec56cd2a0be909b610aa7e`。完整回归 503/503 通过，类型检查通过。隔离 Zotero 10.0.8 首启 10/10、冷重启 8/8 通过，两次使用同一哈希的安装包；实际进程已退出后才开始下一次启动。0.19.2 安装包保持原哈希。

合成 SQLite 数据集包含 69,240 条独立 float32 向量，每条 1024 维，数据库约 406 MiB。所有扫描使用 96 个候选、每页 512 行及八秒截止时间；尾部最优结果位于第 69,240 行，超出缓存后仍能被找到。

| 测量 | 新建 Worker 与空缓存 | 复用前缀缓存 | 独立 32 KiB 缓存溢出 |
| --- | ---: | ---: | ---: |
| Zotero 原生 SQLite 与随包提供的 Worker | 7617 ms | 5239 ms | 6626 ms |
| Node SQLite 与同一随包提供的 Worker | 4638 ms | 3254 ms | 4933 ms |

这里的新建 Worker 表示该次向量运行时和缓存是新的，不表示磁盘与操作系统文件缓存为空。前台八秒还要包括真实查询向量的网络请求，因此这些结果不构成真实云端端到端响应承诺。原生每页 128 行的早期测量曾触发截止取消，本版根据该证据将默认页增至仍有界的 512 行，没有延长八秒预算。额外的故意悬挂请求测试验证超时后当前 PDF 与本地词面结果继续进入实际对话请求。

Worker 的记账缓存峰值为 134,213,648 字节，小于 128 MiB；实际进程总内存还包括 Zotero、SQLite、界面、消息复制与引擎开销。原生父进程在冷扫描前约 791 MB，多次测量中的采样峰值约 2.30 GB；单个主线程页的文字和元数据估计约 5.73 MB。原生主线程 20 ms 心跳的最大间隔分别为 45、153、34 ms。采样不能代表所有瞬时峰值或其他进程的内存，128 MiB 只约束 Worker 记账缓存。

开发验证入口为 `npm test` 和 `npm run typecheck`。先运行 `node scripts/benchmark-rag.cjs <新的性能名称>` 生成合成数据，再运行 `python scripts/cloud-rag-smoke.py --run-name <新的验收名称> --synthetic-db evidence/<新的性能名称>/synthetic-vectors.sqlite`。原生脚本使用最终 XPI 并执行首启与冷重启，两个脚本均拒绝覆盖已有证据目录。发布资产与机器可读校验由整体验证完成后统一整理。
