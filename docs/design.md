# Zotero 区域提问与前文引用：首版设计

日期：2026-10-12  
状态：用户于 2026-10-13 授权执行；已生成 0.10.0 首版，尚未安装到 Zotero 或执行真实 API 验收。以下设计保留审阅时范围。

## 1. 已确认的目标

在现有 Margin Comments (LaTeX custom) 0.9.5 的基础上增加两项功能：

1. 在 Zotero PDF 阅读器中圈选公式、段落或图表，通过 DeepSeek API 提问和追问。
2. 手动圈选前文内容并标记编号，在当前页笔记中按编号引用，直接阅读来源内容。

用户已选择 DeepSeek API；前文定位采用手动框选并标记编号，之后输入编号引用。首版不建立整书 OCR 索引。成功的使用场景是：阅读公式 (7.41) 时，在当前页面展开之前标记的公式 (6.30)，并可将两处原文同时交给 DeepSeek 解释。

## 3. 共用的区域来源

使用 Zotero 原生图片/区域批注承载来源区域，复用其附件、批注标识和 PDF 坐标。新增操作通过区域批注右键菜单进入。

每个来源记录包含：库标识、附件 key、批注 key、PDF 实际页序号、显示页码、区域矩形、来源名称及可选说明。持久化坐标采用 PDF 文档坐标，不采用随缩放改变的屏幕像素。

截图按原始 PDF 页面渲染后裁剪。来源页尚未加载时也能单独渲染，避免必须先滚动到来源页。截图缓存使用附件标识、文件指纹、页码、区域和渲染尺寸作为键；PDF 文件变化后重新生成。

圈选内容、公式、文档文字均作为阅读材料处理，不作为插件操作指令。

## 4. 区域提问

### 4.1 交互

1. 使用 Zotero 区域批注工具圈选内容。
2. 右键选择“向 DeepSeek 提问”。
3. 在阅读器助手面板显示截图、来源页码和问题输入框。
4. 用户可以添加已标记的前文区域，逐项查看和移除本次发送的材料。
5. 点击“发送”后，将问题与所选截图发往 DeepSeek；有可靠文字层时可补充对应文字。
6. 在同一会话中追问，支持停止生成、重新发送和复制回答。
7. 回答支持 LaTeX 预览；需要保存时，用户选择“保存到批注”或“保存为 Zotero 笔记”。

面板绑定当前 PDF 附件。切换文档时切换会话，不混用不同附件的材料。默认发送圈选区域，用户可以显式添加当前页作为上下文，不自动上传整份 PDF。

AI 输出先留在会话中。写入批注使用明确的保存操作和编辑预览，不自动覆盖已有评论；保存为笔记时包含问题、回答、来源名称和可点击的来源定位。

### 4.2 API 设置与调用

- 首版提供 DeepSeek API Key、模型、连接测试设置。
- 官方服务地址为 `https://api.deepseek.com`；首版固定使用官方地址，默认模型为 `deepseek-flash`。
- API Key 使用密码输入框；首版仅在当前 Zotero 会话内保存，重启后重新输入。不放入批注、笔记、截图缓存或日志。
- 通过插件宿主层发起 API 请求，不在 PDF 内容页面中暴露凭据。
- 使用 Chat Completions 的文字与图片消息格式，处理流式输出；追问携带该会话所需的历史和来源材料。
- 图像或上下文过大时在发送前提示用户缩小区域或移除材料，不静默截断公式。
- 认证失败、限流、余额不足和网络失败显示可操作的错误，保留问题和材料。失败后由用户选择重试，不启动无限重试。
- 取消生成保留已收到的文本并标记为未完成；不得把部分结果标为完整回答。

## 5. 手动索引和前文引用

### 5.1 标记来源

1. 在前文框选公式 (6.30) 及需要同时阅读的说明。
2. 右键选择“标记为引用来源”。
3. 输入编号 `6.30`、类型“公式”及可选说明。
4. 在该 PDF 的引用目录中显示缩略图、编号和来源页码，可重命名、修改说明和删除索引。

首版引用类型包括公式、段落、图和表。检索限定为当前 PDF；输入 `6.30`、`(6.30)`、`公式(6.30)` 对公式来源给出相同查询结果。

同一类型和编号出现多个来源时显示候选及页码，由用户选择，不静默覆盖已有标记。删除索引不删除原生区域批注。

### 5.2 当前页阅读

1. 在公式 (7.41) 对应的页边评论中选择“插入引用”。
2. 输入 `6.30`，查看候选缩略图和页码，选择来源。
3. 评论保存一个具名的来源链接；该链接与结构化引用记录对应。
4. 点击链接在当前页旁边展开来源卡片，不改变当前 PDF 阅读位置。
5. 卡片显示原文截图、说明、来源页码，以及“跳转原文”和“加入提问”操作。

引用预览默认一次展开一个来源，也可固定当前来源供对照。来源卡片与现有评论卡片分别管理，避免展开大截图挤占正常评论排版。

插件重新启动后引用仍可恢复。未启用插件时，评论保留可读的编号、来源页码和来源链接。

现有评论编辑器的清理逻辑只保留粗体、斜体、上下标等标签，会移除链接。实现必须增加受限的来源链接读写：只允许插件生成并验证的 Zotero 来源地址，保存、重开及普通文字编辑后仍保留关联，拒绝脚本地址和任意 HTML 属性。

### 5.3 来源异常

- 来源批注删除、附件缺失或 PDF 文件替换时显示“来源已失效”或“需要重新定位”。
- 提供重新关联来源区域的操作；不根据页码猜测并展示另一处公式。
- 库权限为只读时允许查看已有来源，但禁止修改该库中的批注和笔记。

## 6. 数据保存

- 原有评论继续写入 Zotero 原生 `annotationComment`，保留已有自动保存和格式处理。
- 原始区域继续保存在 Zotero 原生区域批注中。
- 引用目录、引用关联和对话草稿保存到插件自己的本地数据目录，按库与附件 key 分组，带格式版本号。
- 本地记录采用临时文件写入后原子替换，避免中断产生半个文件；恢复失败时保留原文件并报告错误。
- 用户明确保存的 AI 回答进入 Zotero 原生笔记或评论；对话草稿不自动写入文献库。
- 首版结构化引用目录和会话草稿仅在当前设备保存，不承诺通过 Zotero Sync 自动同步；原生批注和已保存笔记仍由 Zotero 管理。
- 清除截图缓存不清除索引或笔记；删除会话不删除已经保存的 Zotero 笔记。

## 8. 验收条件

1. **现有功能**：页边卡片、引线、公式预览、类型筛选、编辑保存及便签图标设置保持原有行为。
2. **区域准确性**：文字 PDF 和纯扫描 PDF 均能取得区域截图；缩放、页面旋转、高 DPI 下裁剪与原圈选一致。
3. **跨页引用**：标记 (6.30)，在另一页输入编号后展开正确截图；PDF 实际页序与书内页码不同也能正确定位。
4. **恢复与失效**：重启恢复索引和关联；重复编号可选；来源删除显示失效；缓存清除后能够重建。
5. **联合提问**：发送前可查看两处材料；请求实际包含 (7.41) 和 (6.30) 的截图；答案保存附带可追溯来源。
6. **请求状态**：流式输出、取消、失败重试、401/429 和网络中断不丢问题，不造成重复保存。
7. **数据范围**：不同 PDF 会话隔离；未点击保存不覆盖评论；只读条目不能写入；API Key 不出现在磁盘记录或日志中。
8. **构建交付**：类型检查、核心逻辑测试、阅读器集成测试及 XPI 清单/资源检查通过；生成新版本安装包，保留原包。
9. **证据边界**：模拟请求测试与真实 API 测试分别报告。使用用户在插件中配置的凭据完成至少一次扫描区域提问和追问后，才确认真实 API 可用；在 Zotero 中实际操作后，才确认 GUI 验收。

## 0.12.5 阅读界面与外观

定向参考 Copilot 的会话布局：标题和五个带可访问名称的图标入口、可折叠文档范围、独立滚动消息区、固定底部输入框；用户消息有浅色背景，助手正文去除厚重边框，附件/复制/笔记操作缩为图标。保留原生 textarea、输入焦点标记、Enter/Shift+Enter/IME、选择和 LaTeX 复制行为。配置项全部移入既有原生设置页，侧栏只有当前模型状态。浅深主题使用系统 Canvas/CanvasText 色，18 个宽度/字号/主题组合做几何检查并留存截图。

Host 外观状态采用 Zotero Prefs margincomments.fontSize，校验 12–24 整数，默认 14。只在各面板节点写 CSS 变量，更新不重建 DOM，保留草稿、选区、会话和滚动位置；设置预览和打开的面板即时联动，关闭设置窗口解除监听。不调用 API 保存动作，不重写密钥。

原生 free-text（text）批注内容已绘制在 PDF 页内，因此 shouldDisplayAnnotation 排除该类型，即使 forcedKeys 也不重复页边卡片。其原始条目、文字和 PDF 位置不修改；生成包中移除对应显示复选框，其他类型和前文文字引用不受影响。原始 baseline 与原 XPI 不修改。


## 0.12.6 引用批注气泡

在原有右键引用流程内增加 QuoteBubbles 组件，拥有批注气泡、输入框上方待发送编号及原消息右侧编号锚点。每次只展开一个，保留多条独立草稿；引用选择的 messageIndex 与 DOM 文本 start/end 用于定位图标，不在原回答里注入文本或重写公式。滚动、字号/面板尺寸变化时重算锚点；不可见锚点可从输入框编号重开。公式选区继续使用既有 clipboard LaTeX 扩展规则，气泡只用安全 MathML 渲染。

通过文档捕获阶段监听 pointerdown，兼容聊天区停止冒泡的剪贴板保护，并绑定已有嵌套 PDF frame 文档；空白批注自动删除，有内容只收起，Escape 和关闭侧栏也收起。解除监听、观察器与计时器跟随面板销毁。批注输入沿用 contenteditable 标记的原生 textarea，支持光标、复制/粘贴和 IME；不将 Enter 解释为提交整段问题。

会话增加可选 draftQuotes 数组（最多20），每条仅有 id/text/comment/messageIndex/可选数字偏移；老 v1/v2 数据兼容，不升级结构版本、不覆盖旧历史。长度与关联索引由 cleanState 校验，沿用原 JSON 原子写入和本地保存路径。输入延迟保存，收起/关闭/切换即保存。批注原文最多12000字符、评论4000字符；剪贴板插入绕过原生 maxLength 的情况也在 input 时约束。

send() 在原问题前后拼接全部有内容的引用批注，复用当前 PDF、附件、摘要和容量预检。可只发批注。生成失败/停止保留待发送批注，速度重试比较合并问题以避免重复问答；成功后清空待发送气泡，原始引用与评论保留在已发送问题中。生成期间冻结批注编辑，避免发出后丢失新增草稿；输入框新改文字继续沿用原有保留规则。


## 0.12.7 PDF 选区批注气泡

沿用 QuoteBubbles，draftQuotes 每条可为对话 messageIndex 锚点或 source PDF 来源，不改变 v2 状态版本。文字菜单冻结 selectionSnapshot，转为 selection:true/kind:text/page/rects/text/fingerprint，只存当前 PDF 的原文快照，不写 Zotero 永久高亮，允许只读文库提问。已有高亮/下划线与 image 区域沿用原生 annotationKey。capture/resolveSource 继续检查附件归属和文件指纹；失效选区依既有策略带说明省略新读取，问题中的原文标作选区快照，未知错误仍中止且保留草稿。临时文字选区链接仅跳页，不伪装成可保存答案的原生批注目标。

在真实 PDF iframe 创建独立的透明、pointer-events:none 覆盖层，只有编号和气泡接收事件，不更改页面宽度或注入源文字。source.rects 通过当前 page.viewport 换算，结合页面实际 DOM 尺寸处理缩放/旋转，监听滚动、resize、PDF.js page/scale/rotation 事件重定位；页面不可见时隐藏编号，输入框入口仍可重开并跳页。Zotero 跨窗口转换采用数值逐点传递，避免 PDF 窗口读取特权脚本数组的权限错误。PDF 覆盖层安装自己的 MathML 样式和剪贴板行为；销毁时移除覆盖层、所有监听与资源。

PDF 文字/区域可与对话批注混用：发送前重新 capture 每个有内容的 PDF 批注，按来源去重，原文和截图进入既有材料管线，页码和对应编号进入合并问题；history.materials 保留来源，草稿 JSON 不保存图像编码。总材料数仍为8，批注总数20；成功清空待发送批注，失败/取消保留。气泡位于 PDF 子文档，关闭助手或切换非聊天视图隐藏覆盖层，重开恢复编号。
