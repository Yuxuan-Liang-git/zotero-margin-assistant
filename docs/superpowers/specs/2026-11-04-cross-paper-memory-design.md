# 跨论文研究记忆设计

日期为2026-11-04，基线版本为0.16.0，拟交付版本为0.17.0。本文件用于实现前确认。

### 阅读目标与已确定范围

用户希望在讨论A论文时，助手能够主动联系此前阅读B论文时讨论过的结论，说明关联与适用条件，并提供回到原资料的入口。用户已经选定首版资料范围为插件保存的对话和阅读摘要。

每份PDF同目录的历史JSON继续作为会话与阅读摘要的权威记录。研究记忆是由这些记录派生的本地检索索引。对话时检索相关材料，将必要片段连同明确的来源信息加入本轮请求，再由当前选择的ChatGPT或DeepSeek解释它们与当前问题的关系。

当前ChatGPT订阅接入按请求传入上下文，使用 `store:false`。官方授权提供账户身份及订阅用量，插件目前缺少访问网页对话的授权。此次功能的交付目标是插件内跨论文关联，同时提供研究笔记导出，供用户加入ChatGPT项目后复用。[官方授权说明](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt) · [订阅接入限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

### 方案与默认选择

已选定的方向是在插件内建立统一研究记忆。原有按PDF保存的会话结构和阅读摘要提供原始资料，增量索引负责跨文献检索。ChatGPT网页聊天列表的同步需要额外的平台能力，网页端复用采用导出后的项目资料。

检索实现拟采用本地文本分词与BM25相关性排序，结合论文标题、当前问题及最近讨论的主题，优先命中明确指定的论文。中文采用字词片段，英文保留技术词、缩写和公式附近的文本。它适合现有订阅接入与Windows桌面环境，索引建立和检索可以直接在本机完成。外部向量服务会增加账户及网络依赖，本地嵌入模型会增加模型下载、内存和启动成本。因此首版采用本地文本检索，这项实现选择由设计者提出，待用户随本设计确认。跨语言表达及词汇重合较少的关联需要专门的检索质量验收。

默认在当前PDF所属的Zotero文献库内检索，覆盖该库中已有插件记录的论文。不同文献库分别建索引。默认开启跨论文记忆，设置中提供开关、索引进度和重建索引入口。这些默认值由设计者提出。

### 索引资料与来源

索引收录已完成的用户提问与助手回答，以及已保存的正式阅读摘要。每个片段携带文献库ID、PDF附件key、论文标题、年份、DOI、资料类型、会话ID、消息位置、内容签名和可确认的记录时间。现有会话具有更新时间，摘要具有正式更新时间，界面据此标注“会话更新”或“摘要更新”。旧记录的时间为零时显示时间未知。原问答中已有的页码与公式编号可作为附加来源线索。用户问题和助手解释分别标注，模型据此区分用户观点、历史解释与论文原文。

摘要优先提供已经整理过的理解，原问答保留具体推导、条件和纠正的出处。索引按自然段及问答边界切分文本，保留数学定界符和LaTeX内容。未发送草稿、生成失败的未完成回答和待发布摘要候选采用独立状态，首版检索收录正式记录。记录有人工编辑冲突时，历史摘要在再次使用前校验其关联笔记，发现已被改写则暂时移出检索，并保留原问答作为可检索材料。

同一PDF的其他会话和正式摘要也可被检索。当前会话已经携带的消息、相同内容的摘要片段，以及同一来源的重复片段在组装请求时去重。结果优先覆盖不同论文，默认最多引入三篇论文。

### 本地保存与历史回填

派生索引保存在Zotero数据目录下的 `margin-comments-assistant/research-memory/`。各文献库保存独立目录清单与按附件拆分的文本索引，清单记录索引格式、原记录指纹、更新时间与索引状态。这个位置适用于Zotero导入附件及链接到其他本地目录的PDF，实际PDF路径由Zotero附件条目解析。

首次启用后后台枚举当前文献库的PDF附件，分批检查PDF同目录的插件历史文件，并兼容旧版集中保存的历史路径。只处理实际存在的插件记录，逐篇读取、校验和索引。历史回填采用纯读解析路径，通过 `C.cleanState` 校验内存副本。既有 `Host.load()` 带有创建历史入口笔记的副作用，回填采用前述纯读路径。旧版记录可在内存中转换为索引输入。

索引文件采用临时文件加原子替换。每个文献库的写入串行化，更新任务按附件合并，提交时校验版本，较早的后台任务只能提交与其输入一致的结果。索引格式升级和损坏可通过原始记录重建。个别记录无法读取时保留可用索引及错误状态，设置中展示跳过数量和原因。

历史回填在阅读器就绪后的空闲阶段运行。逐篇异步IO、分批文本处理和主动让出事件循环共同限制主线程占用。单个文件和索引片段设置读取与处理上限，超大记录显示可核查的跳过状态。实现时根据既有导入限制和大历史夹具确定这些上限，并写入验收记录。首轮索引尚未完成时，提问使用已就绪的有效索引，后台继续补齐余下资料。

### 更新与一致性

一次完整回答、历史导入成功及正式阅读摘要更新后，相关PDF加入增量更新队列。仅改动输入框草稿和流式回答片段时，索引合并等待最终记录。索引提交以持久化成功后的状态为依据。

启动时从本地恢复索引，在后台检查原记录的文件指纹。候选片段真正进入模型请求前，再校验对应附件、会话和内容签名，跳过已删除、被替换或损坏的资料，并安排刷新。PDF路径发生变化时通过附件key重新解析，来源跳转采用Zotero附件和会话标识。

后台更新在前台提问期间暂停大批量工作，取消和插件停用会终止尚未提交的任务。多个阅读器共享同一索引管理器，缓存按文献库及附件设置大小上限。索引模块异常通过独立状态显示，提问流程可继续使用当前论文与当前会话。

### 检索与请求预算

每次发送时，根据当前问题、论文标题及近期少量已完成讨论构造查询。索引先筛选论文，再排序片段。明确提到B论文标题或DOI时优先定位该论文，返回结果仍校验其可读性和内容。一般问题设置相关性阈值，跨论文材料按实际命中进入上下文。

首版拟将研究记忆文本控制在最多6000字符，单个片段最多1800字符，每次最多三篇论文，并纳入现有总上下文预算。当前问题、明确添加的材料和当前PDF优先取得预算，研究记忆使用剩余空间。具体阈值与分段细节由实现者通过相关及无关论文夹具验证。检索和索引通过本地代码完成，本轮被选中的历史文字随正常提问发送给当前AI服务。

请求中的历史片段标记为带出处的资料。模型根据片段解释已有讨论的联系，并区分原文、历史解释、用户判断及待验证推断。片段中的指令文字按资料处理，回答只能引用本轮实际提供的研究记忆来源。缺少适用条件时，回答需说明需要核对的条件。

### 界面与来源跳转

沿用紧凑的助手界面，设置中集中放置跨论文记忆开关、索引状态和重建入口。本轮有命中时，在回答附近提供可折叠的“参考过的阅读记录”，显示论文、资料类型、简短摘录和记录时间。历史回答保存其实际使用的来源标识及必要摘录，重开后可核对当时的回答依据。

点击来源后，摘要来源打开对应论文的阅读摘要，问答来源打开对应PDF及会话并定位原消息。目标已删除时显示明确状态。来源引用由插件按本轮检索清单生成，采用受控的附件、会话和消息标识解析，渲染时进行文本转义。正常正文中保留轻量的引用标记，展开内容按需渲染，避免为长历史一次性创建全部DOM。历史消息增加可选且有长度限制的来源元数据，旧记录沿用既有版本读取；校验、保存、重开和导入导出路径共同处理这些字段。

### 网页端复用

设置中提供“导出研究笔记”，经现有文件选择器保存一份Markdown。内容按论文标题组织正式阅读摘要，附文献信息和记录时间，数学使用原有LaTeX语法。该导出以可独立阅读的摘要正文为主体。用户可将文件加入ChatGPT项目的资料中继续讨论，后续更新通过再次导出和替换项目资料完成。[ChatGPT项目资料说明](https://learn.chatgpt.com/docs/projects)

### 验证与交付

核心回归覆盖中文及英文查询、标题精确定位、相近与无关主题、公式文本、同一来源去重、当前会话排除、预算优先级、不同文献库隔离，以及没有正式摘要时检索已完成问答。索引回归覆盖首次回填、旧路径、冷恢复、导入与摘要更新、并发保存、损坏缓存、超大记录、删除来源、摘要人工编辑冲突及取消后的任务提交。

浏览器回归通过正常发送入口验证A论文的请求包含B论文的相关记录，并显示可打开的来源。关闭记忆、无相关命中及来源校验失败均有对应请求检查。大历史夹具记录事件循环心跳及渲染规模，重点复现用户曾报告的整个Zotero卡住问题。

隔离Zotero原生验证使用两篇测试PDF、已知会话和摘要，检查自动回填、跨论文发送、来源跳转、设置恢复和冷重启。推理使用可检查输入的模拟响应，真实账户的关联质量验收另行标明。完整回归、全源码checkJs及安装包资源校验通过后生成XPI和源码归档，验收报告关联最终包哈希。

### 确认内容

用户已确定资料范围。待确认的设计者选择为同一文献库内自动关联、默认启用、本地文本检索、最多三篇论文及6000字符的初始预算，以及正式摘要的Markdown导出。其余算法阈值、分批尺寸、缓存上限、状态文案和回归夹具由实现者在上述契约内决定。
