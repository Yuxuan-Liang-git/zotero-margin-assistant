# 0.13.6 性能排查与验证

## 已确认的问题及修改

旧版 `Host.watchToolbar` 对阅读器整个 body 做深层 DOM 监听，每次聊天输出也运行工具栏恢复检查。新版监听工具栏及其直接父容器，过滤无关变动并合并同轮检查；工具栏重建时重新绑定。工具栏尚未挂载时使用临时的候选节点发现监听，发现后立即断开并切换为局部监听；关闭时清理全部监听。

旧版 `Host.save` 在每次草稿或聊天记录保存后刷新该 PDF 的引用卡片。新版比较来源、引用、图片记录的签名，仅这些数据变化时刷新；保留保存顺序和导入期间的写入等待。修改或删除索引仍使卡片更新。

旧版所有 Zotero item 通知都强制刷新全部阅读器。新版修改事件按 PDF 或其子批注定位受影响的阅读器，删除事件保留保守的全局失效检查。来源实际使用时的坐标、文字和文件指纹校验继续有效。

未修改原始 baseline。未改变历史文件格式、授权配置、输入方式、公式渲染或正文内容。没有为尚未复现的假设添加复杂缓存或异步渲染逻辑。

## 浏览器压力与回归

`tests/performance.test.cjs` 检查无关变动过滤、工具栏恢复/重新绑定、索引修改刷新、条目作用域和保存等待。`tests/stress-performance.test.cjs` 覆盖 20 条可见消息中的 40 个公式、重复切换显示、LaTeX 复制、200 条消息导入与逐批展开、定时流式输出期间继续输入及正文完整性。具体机器计时写入 `evidence/ui-0136/stress-performance.json` 和 `stress-stream-import.json`，不作为跨机器速度承诺。

首轮全量回归发现工具栏延迟挂载的边界回归（211/212），已补上临时发现监听并保留原测试，初轮记录为 `evidence/ui-0136/tests-initial.txt`。最终全量回归 213/213 通过（137.1 秒），记录保存到 `evidence/ui-0136/tests-final.txt`；完整 src checkJs 通过。独立复核未发现剩余问题。打包结果见 `dist/verification-report.json`。

## 边界

本轮未复现用户描述的整窗卡死，确认并修复的是无关刷新放大。现有测试不能排除超大扫描 PDF、特殊公式、长时间累计使用或其他插件组合的问题。保留原始完整对话和来源数据；未通过丢弃内容或停用公式实现优化。
