# 个人文献库论文记忆0.18.0

### 使用方式

覆盖安装0.18.0并完全退出、重新打开Zotero。插件随后在本地分批发现整个个人文献库，包含全部分类文件夹。先同步书目信息与已有笔记，再读取已有文字缓存，最后逐篇补充PDF正文。论文可以在尚未建立任何插件对话时参与检索。

在“设置→页边批注→跨论文研究记忆”查看文献总数、元数据就绪数、PDF正文就绪及待处理情况。后台索引可以暂停、继续或重建，手动暂停会在重启后保留。前台提问或导入对话会优先使用资源，结束后继续后台工作。

正常提问会在剩余预算内加入命中的其他论文资料。回答附近的折叠来源区区分文献摘要、论文正文、Zotero笔记、PDF标注、阅读摘要与历史问答。点击来源可打开原条目、笔记、PDF页或历史会话。缺少可靠页号的普通文字缓存通过PDF搜索定位，来源区保留实际提供的节选。

### 覆盖与本地保存

同一论文属于多个分类时只记为一篇，多个PDF附件保留各自身份。只有书目信息的条目仍可通过标题、作者、年份、DOI、摘要和标签参与引用。插件历史入口快捷笔记从正文资料中排除，正式阅读摘要沿用原有权威记录与人工改写保护。

新的派生索引位于Zotero数据目录的 `margin-comments-assistant/research-memory/papers-v1.sqlite`。原有历史索引继续保存在该目录下按文献库组织的JSON文件。原聊天和阅读摘要仍从PDF旁的权威文件读取，PDF、Zotero笔记和标注各自保留权威身份。

正文按页及段落保存，倒排词表由独立SQLite连接查询，长文献末尾的词项也会纳入。新通道覆盖整个个人文献库，旧对话通道的2000篇、每篇256000字符或512段上限继续单独计量。

文件、已有全文缓存和结构化缓存的身份参与校验。来源在进入本轮请求或被点击前重新验证。文件替换、缓存更新、笔记编辑或条目删除会使旧片段失效，并触发重新发现。未完成的后台代际不会对检索可见，提取失败时保留仍有效的已提交部分缓存。

### 资源与质量边界

本地后台处理每次只提取一个PDF，自动提取的单文件上限为64 MiB。更大的PDF优先复用已有文字缓存，并展示大文件待处理状态。纯扫描页显示需要OCR，已有OCR文字层可以直接使用。部分文字、缺失文件、需要密码和提取失败分别显示。异常单页文字超过2097152字符时跳过该页并标记部分覆盖。

正文提取可能遗漏图像公式、复杂排版或图表中的信息。关联来源代表本轮实际提供的文字节选。索引过程在本机执行，命中的节选随正常问题提交给当前AI服务。本次后台任务执行本地文字提取与索引。

每次最多引入三篇论文，关联上下文最多6000字符，单片段最多1800字符，并同时受现有请求体积限制。当前问题、明确附件与当前PDF先取得预算。候选排序结合本次问题与词项稀有度，并限制单篇候选数量，减少重复正文挤掉末页关键词的情况。相关性使用本地词项匹配，跨语言同义表达和实际语料的关联质量仍受词汇覆盖影响。

“导出研究笔记”继续汇总正式阅读摘要，并追加明确标为文献资料的书目信息与正文覆盖情况，便于在其他研究环境中复用。
